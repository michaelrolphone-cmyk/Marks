APPS

2. GET /api/apps
   Purpose: returns app catalog used by the launcher.
   Returns: JSON object with field "apps": array.

   Response dataset (nested server payload):

* AppCatalogPayload:

  * apps: AppEntry[]

* AppEntry (fields observed/assumed by launcher):
  Required:

  * entryHtml: string
  * name: string
  * iconPath: string
    Optional/commonly present:
  * description?: string
  * section?: string
  * experimental?: boolean
  * iconHeight?: number
  * id?: string

  Notes (launcher-derived):

* launcher filters out any app whose entryHtml is "index.html" (case-insensitive)

* launcher treats entryHtml as the iframe entry file (path-like string)

* launcher selects an app by matching entryHtml exactly to the requested file path (after stripping leading "/")

4. GET /api/lookup?address=...
   Purpose: address lookup that returns a location plus PLSS feature context (township/section).
   Query:

* address: string (required)

  Returns (minimum required by launcher):

* LookupPayload:

  * location: { lat: number, lon: number }
  * section: FeatureLike
  * township: FeatureLike

  FeatureLike dataset (nested server object expected by launcher):

* FeatureLike:

  * attributes: object (required)
  * geometry?: object (optional/ignored by launcher)
  * (other keys allowed; ignored)

  Township/Range/Section attribute keys explicitly consumed by launcher (nested under FeatureLike.attributes):

* Township number (first non-empty among):

  * TWNSHPNO
  * TOWNSHIP
  * TWP
  * TWP_NO
  * Fallback: first attribute key matching /TWP|TOWNSHIP|TWNSHP/i

* Township direction (uppercased by launcher; first non-empty among):

  * TWNSHPDIR
  * TOWNSHPDIR
  * TWPDIR
  * TOWNSHIP_DIR
  * TDIR
  * Fallback: first attribute key matching /TWP.*DIR|TOWNSHIP.*DIR|TWNSHP.*DIR/i

* Range number (first non-empty among):

  * RANGENO
  * RANGE
  * RNG
  * RANGE_NO
  * Fallback: first attribute key matching /RNG|RANGE/i

* Range direction (uppercased by launcher; first non-empty among):

  * RANGEDIR
  * RNGDIR
  * RANGE_DIR
  * RDIR
  * Fallback: first attribute key matching /RANGE.*DIR|RNG.*DIR/i

* Section number (first non-empty among):

  * SEC
  * SECTION
  * SECNO
  * Fallback: first attribute key matching /SEC|SECTION/i

  Section parsing note (launcher-derived):

* launcher accepts raw numeric section strings (1–2 digits)

* launcher also extracts embedded patterns like “SEC 12”, “SECTION #12”, etc.

  Notes (launcher-derived):

* launcher uses lookupPayload.location.lat/lon to optionally call /api/aliquots

* launcher tolerates missing/empty township/section attribute values (results in incomplete townshipRange label)

7. GET /api/aliquots?lon=...&lat=...&outSR=4326
   Purpose: find aliquot (quarter/quarter-quarter) feature(s) for a coordinate.
   Query:

* lon: number
* lat: number
* outSR: spatial reference WKID (optional; launcher calls without outSR)

  Returns (minimum required by launcher):
* AliquotsPayload:

  * aliquots: FeatureLike[]

  FeatureLike.attributes keys used by launcher (nested selection rule):
* launcher picks the FIRST non-empty aliquot code from:

  * feature.attributes.ALIQUOT
  * else feature.attributes.NAME

  Aliquot code normalization assumptions (launcher-derived; impacts downstream use):
* code is uppercased and stripped to only NSEW letters
* launcher derives a quarter-sequence only when:

  * normalized length is even AND
  * every 2-letter chunk is one of: NE, NW, SE, SW
* if that condition fails, launcher still may display aliquotLabel, but will not derive a usable quarter-sequence for “sectionQuadrant + aliquots” encoding.

20. WS /ws/crew-presence
    Purpose: realtime presence channel for which crew members are online.

Server -> client messages (launcher-derived schema):

* CrewPresenceWelcome:

  * type: "crew-presence-welcome"
  * online: string[]        (crewMemberId list)
* CrewPresenceUpdate:

  * type: "crew-presence-update"
  * online: string[]        (crewMemberId list)

  Client -> server messages (launcher-derived schema):
* CrewPresenceIdentify:

  * type: "crew-presence-identify"
  * crewMemberId: string|null

  Notes (launcher-derived):
* crewMemberId can be null when user hasn’t selected an identity.
* server should associate socket sessions with crewMemberId and compute the online[] list accordingly.
